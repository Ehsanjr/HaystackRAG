# Haystack RAG Pipeline

پیاده‌سازی یک پایپ‌لاین **Retrieval-Augmented Generation (RAG)** با استفاده از Haystack و بررسی نحوه اتصال آن به ابزارهای مکمل برای پردازش اسناد، جست‌وجوی معنایی، تولید پاسخ و ارائه API.

## معرفی پروژه

هدف این پروژه، جست‌وجو، بررسی و پیاده‌سازی عملی یک معماری RAG با تمرکز بر شناخت قابلیت‌های Haystack و نحوه ارتباط آن با سایر ابزارهای موردنیاز است.

در این پروژه، یک جریان پردازش اطلاعات پیاده‌سازی شده که اسناد متنی را دریافت می‌کند، آن‌ها را به قطعه‌های کوچک‌تر تقسیم می‌کند، بردارهای معنایی تولید می‌کند، داده‌ها را در پایگاه داده برداری ذخیره می‌کند و در زمان دریافت پرسش، اطلاعات مرتبط را بازیابی کرده و برای تولید پاسخ در اختیار مدل زبانی قرار می‌دهد.

تمرکز اصلی پروژه بر شناخت نقش هر ابزار و نحوه اتصال آن‌ها برای ساخت یک پایپ‌لاین کامل است، نه توسعه یک محصول نهایی.

## اهداف

- آشنایی عملی با Haystack و مفهوم Pipeline.
- بررسی فرایند پردازش و قطعه‌بندی اسناد.
- آشنایی با Embedding و جست‌وجوی معنایی.
- اتصال Haystack به پایگاه داده برداری Qdrant.
- اتصال مدل زبانی محلی با استفاده از Ollama.
- پیاده‌سازی بازیابی اطلاعات با فیلترهای مبتنی بر فراداده.
- ارائه قابلیت‌های پایپ‌لاین از طریق FastAPI.
- بررسی نحوه اتصال Open WebUI به API پروژه.
- شناخت مسئولیت هر ابزار در معماری RAG.

## معماری پروژه

```text
                    User
                     |
                     v
                 Open WebUI
                     |
                     v
                  FastAPI
                     |
                     v
               Haystack Pipeline
                /            \
               v              v
       Sentence Transformers  Ollama
               |           Llama 3.2
               v              ^
             Qdrant -----------+
        Vector Database
```

در این معماری، Haystack جریان اجرای مراحل بازیابی و تولید پاسخ را مدیریت می‌کند. Sentence Transformers برای تبدیل متن به بردار، Qdrant برای ذخیره‌سازی و بازیابی اطلاعات، Ollama برای اجرای مدل زبانی و FastAPI برای ارائه قابلیت‌های پایپ‌لاین استفاده می‌شوند.

Open WebUI نیز به‌عنوان رابط چت، امکان ارسال پرسش‌ها به API را فراهم می‌کند.

## فرایند پردازش اطلاعات

### ۱. بارگذاری اسناد

اسناد متنی با پسوند `.txt` از پوشه اسناد خوانده می‌شوند. محتوای فایل‌ها بررسی شده و اطلاعات موردنیاز برای مراحل بعدی استخراج می‌شود.

### ۲. استخراج فراداده

اطلاعات تیم و سطح محرمانگی از نام فایل استخراج می‌شوند.

الگوی نام‌گذاری:

```text
<team>-<confidentiality>.txt
```

نمونه فایل‌ها:

```text
hamta-private.txt
hamta-public.txt
karbordi-private.txt
karbordi-public.txt
```

مقادیر مجاز در پیاده‌سازی فعلی:

- `team`: مقادیر `hamta` و `karbordi`
- `confidentiality`: مقادیر `private` و `public`

این اطلاعات به‌عنوان Metadata به اسناد اضافه می‌شوند تا در مراحل بعدی برای محدودکردن دامنه جست‌وجو قابل استفاده باشند.

### ۳. قطعه‌بندی اسناد (Chunking)

برای بهبود فرایند بازیابی، اسناد به قطعه‌های کوچک‌تر تقسیم می‌شوند.

تنظیمات فعلی:

- اندازه قطعه: ۸۰۰ کاراکتر
- هم‌پوشانی قطعه‌ها: ۱۵۰ کاراکتر

فراداده‌های سند اصلی به قطعه‌های تولیدشده منتقل می‌شوند. همچنین اطلاعاتی مانند شماره قطعه و محدوده متنی آن ذخیره می‌شوند.

در اجرای فعلی، ۲۶ قطعه متنی برای نمایه‌سازی آماده شده است.

### ۴. تولید بردارهای معنایی (Embedding)

برای تبدیل متن به بردار از مدل زیر استفاده می‌شود:

`sentence-transformers/all-MiniLM-L6-v2`

بردارهای حاصل، نمایش عددی متن هستند و برای مقایسه شباهت معنایی میان پرسش کاربر و قطعه‌های اسناد استفاده می‌شوند.

ابعاد بردارهای تولیدشده برابر با ۳۸۴ است.

### ۵. ذخیره‌سازی در Qdrant

بردارهای اسناد همراه با محتوای متنی و فراداده‌های مربوطه در Qdrant ذخیره می‌شوند.

تنظیمات فعلی:

- آدرس سرویس: `http://localhost:6333`
- نام Collection: `persian_documents_v1`
- ابعاد بردار: `384`

Qdrant در زمان دریافت پرسش، امکان بازیابی قطعه‌های مرتبط بر اساس شباهت برداری را فراهم می‌کند.

### ۶. بازیابی اطلاعات (Retrieval)

در زمان دریافت پرسش، متن پرسش با استفاده از مدل Embedding به بردار تبدیل می‌شود. سپس Haystack از طریق بازیاب Qdrant، قطعه‌های مرتبط را جست‌وجو می‌کند.

تعداد نتایج بازیابی‌شده در تنظیمات فعلی برابر با سه قطعه است:

`TOP_K = 3`

علاوه بر شباهت معنایی، امکان اعمال فیلتر بر اساس فراداده نیز پیاده‌سازی شده است.

برای مثال، می‌توان بازیابی را به اسنادی محدود کرد که متعلق به تیم `hamta` و دارای سطح محرمانگی `private` هستند.

فیلترها با عملگر `AND` ترکیب می‌شوند تا تمام شرایط انتخاب‌شده به‌صورت هم‌زمان برقرار باشند.

### ۷. تولید پاسخ (Generation)

برای تولید پاسخ از Ollama و مدل زبانی زیر استفاده می‌شود:

`llama3.2:latest`

آدرس سرویس Ollama:

`http://localhost:11434`

پس از بازیابی اسناد مرتبط، محتوای آن‌ها به‌عنوان زمینه در اختیار مدل زبانی قرار می‌گیرد. مدل با استفاده از پرسش کاربر و زمینه بازیابی‌شده پاسخ را تولید می‌کند.

در دستورالعمل تولید پاسخ تأکید شده است که مدل بر اطلاعات موجود در اسناد تکیه کند و در صورت مشخص‌نبودن پاسخ در اطلاعات بازیابی‌شده، این موضوع را اعلام کند.

### ۸. ارائه API با FastAPI

برای فراهم‌کردن امکان دسترسی به پایپ‌لاین از طریق سایر برنامه‌ها، API با استفاده از FastAPI پیاده‌سازی شده است.

آدرس API:

`http://localhost:8000`

نقاط پایانی اصلی:

| Endpoint | کاربرد |
|---|---|
| `/health` | بررسی وضعیت سرویس |
| `/v1/models` | ارائه اطلاعات مدل |
| `/v1/chat/completions` | دریافت پرسش و تولید پاسخ |

API درخواست‌ها را دریافت می‌کند، پارامترهای موردنیاز را استخراج می‌کند و نتیجه اجرای پایپ‌لاین را برمی‌گرداند.

در ساختار درخواست چت، پارامترهای `team` و `confidentiality` نیز پشتیبانی می‌شوند.

همچنین حالت Streaming پیاده‌سازی شده است. در نسخه فعلی، پاسخ ابتدا به‌طور کامل تولید می‌شود و سپس در قطعه‌های متوالی ارسال می‌شود؛ بنابراین این قابلیت، ارسال جریانی خروجی است و نه تولید توکن‌به‌توکن توسط مدل.

### ۹. اتصال Open WebUI

Open WebUI برای بررسی اتصال یک رابط چت به API پروژه راه‌اندازی شده است.

آدرس رابط کاربری:

`http://localhost:3000`

نسخه مورد استفاده:

`v0.12.3`

از آنجا که Open WebUI در Docker اجرا می‌شود و API روی میزبان ویندوز قرار دارد، آدرس API از داخل کانتینر به شکل زیر تنظیم شده است:

`http://host.docker.internal:8000/v1`

شناسه مدل مورد استفاده:

`haystack-rag`

این اتصال امکان ارسال درخواست‌های چت از Open WebUI به پایپ‌لاین Haystack را فراهم می‌کند.

**محدودیت فعلی:** اگرچه API از پارامترهای تیم و سطح محرمانگی پشتیبانی می‌کند، رابط استاندارد Open WebUI این پارامترهای سفارشی را به‌صورت خودکار ارسال نمی‌کند. برای ارائه کنترل‌های انتخاب تیم و محرمانگی مستقیماً در رابط Open WebUI، به یکپارچه‌سازی سفارشی نیاز است. این بخش هنوز تکمیل نشده است.

## ساختار کد

ماژول‌های اصلی پروژه بر اساس وظیفه تفکیک شده‌اند:

```text
Haystack/
├── documents/
│   ├── hamta-private.txt
│   ├── hamta-public.txt
│   ├── karbordi-private.txt
│   └── karbordi-public.txt
│
├── src/
│   ├── api.py
│   ├── config.py
│   ├── loader.py
│   ├── chunker.py
│   ├── embedder.py
│   ├── vector_store.py
│   ├── indexing.py
│   ├── retriever.py
│   └── rag_pipeline.py
│
└── venv/
```

**توضیح ماژول‌ها:**

- `config.py`: تنظیمات مشترک پروژه، مانند نام Collection و اندازه قطعه‌ها.
- `loader.py`: بارگذاری اسناد و استخراج فراداده.
- `chunker.py`: تقسیم اسناد به قطعه‌های متنی.
- `embedder.py`: آماده‌سازی مدل و تولید بردارهای معنایی.
- `vector_store.py`: پیکربندی مخزن برداری.
- `indexing.py`: اجرای فرایند نمایه‌سازی اسناد.
- `retriever.py`: بازیابی اسناد و اعمال فیلترها.
- `rag_pipeline.py`: تعریف و اجرای جریان بازیابی و تولید پاسخ.
- `api.py`: ارائه قابلیت‌های پایپ‌لاین از طریق FastAPI.

این ساختار بر اساس ماژول‌های استفاده‌شده در پیاده‌سازی فعلی مستند شده است.

## راه‌اندازی محیط توسعه

### پیش‌نیازها

- Python و محیط مجازی
- Docker
- Qdrant
- Ollama
- مدل `llama3.2`
- وابستگی‌های پایتون پروژه

### ۱. ورود به پوشه پروژه

در Windows CMD:

```bat
cd /d D:\Ehsan\Haystack
```

### ۲. فعال‌سازی محیط مجازی

```bat
venv\Scripts\activate
```

اگر محیط مجازی از قبل ساخته نشده باشد:

```bat
python -m venv venv
venv\Scripts\activate
```

### ۳. نصب وابستگی‌ها

اگر فایل `requirements.txt` در پروژه موجود است:

```bat
python -m pip install -r requirements.txt
```

در غیر این صورت، وابستگی‌های مورد استفاده باید مطابق محیط پروژه نصب شوند. ثبت نسخه دقیق بسته‌ها در `requirements.txt` برای بازتولید محیط توصیه می‌شود.

### ۴. آماده‌سازی مدل زبانی

در صورت نیاز، مدل را از طریق Ollama دریافت کنید:

```bat
ollama pull llama3.2
```

### ۵. اجرای سرویس‌ها

اطمینان حاصل کنید که Qdrant و Ollama در دسترس هستند.

Qdrant باید روی پورت `6333` و Ollama روی پورت `11434` قابل دسترسی باشند.

### ۶. نمایه‌سازی اسناد

پیش از پرسش‌وپاسخ، اسناد باید از طریق ماژول نمایه‌سازی پروژه پردازش و در Qdrant ذخیره شوند.

دستور دقیق اجرای نمایه‌سازی باید با فایل‌های اجرایی موجود در نسخه محلی پروژه تطبیق داده شود.

### ۷. اجرای API

از ریشه پروژه و در محیط مجازی:

```bat
python -m uvicorn src.api:app --host 0.0.0.0 --port 8000
```

پنجره CMD را تا زمانی که API موردنیاز است باز نگه دارید.

### ۸. بررسی وضعیت API

در یک پنجره CMD جدید:

```bat
curl.exe http://localhost:8000/health
```

برای بررسی مدل‌های ارائه‌شده:

```bat
curl.exe http://localhost:8000/v1/models
```

## نمونه درخواست

نمونه زیر یک پرسش را همراه با فیلتر تیم و محرمانگی ارسال می‌کند:

```bat
curl.exe -X POST http://localhost:8000/v1/chat/completions ^
  -H "Content-Type: application/json" ^
  -d "{\"model\":\"haystack-rag\",\"messages\":[{\"role\":\"user\",\"content\":\"سیاست تراکنش چیست؟\"}],\"team\":\"hamta\",\"confidentiality\":\"private\",\"stream\":false}"
```

در این نمونه، بازیابی به اسناد تیم `hamta` با سطح محرمانگی `private` محدود می‌شود.

پاسخ API شامل محتوای پاسخ تولیدشده است و در حالت غیرجریانی، اطلاعات منابع بازیابی‌شده نیز در فیلد سفارشی `sources` برگردانده می‌شوند.

## محدودیت‌ها و ملاحظات

- این پروژه با هدف جستجو و پیاده‌سازی آموزشی توسعه یافته و آماده بهره‌برداری سازمانی محسوب نمی‌شود.

## جمع‌بندی

Haystack چارچوبی برای طراحی، سازمان‌دهی و اجرای پایپ‌لاین‌های پردازش اطلاعات و RAG است. این ابزار به‌تنهایی تمام نیازهای یک سامانه کامل را برطرف نمی‌کند، بلکه با ابزارهای تخصصی دیگر ارتباط برقرار می‌کند و جریان اجرای آن‌ها را مدیریت می‌کند.

در این پروژه، Haystack به Sentence Transformers برای تولید بردارهای معنایی، Qdrant برای ذخیره‌سازی و بازیابی اطلاعات، Ollama و Llama 3.2 برای تولید پاسخ، FastAPI برای ارائه API و Open WebUI برای بررسی اتصال رابط چت متصل شده است.

این پیاده‌سازی مسیر پردازش اسناد تا بازیابی اطلاعات و تولید پاسخ را به‌صورت عملی نشان می‌دهد و نمونه‌ای از نحوه همکاری ابزارهای مختلف در ساخت یک پایپ‌لاین RAG فراهم می‌کند.

دستاورد اصلی پروژه، شناخت نقش هر ابزار، نحوه ارتباط میان آن‌ها و اهمیت هماهنگ‌سازی اجزای مختلف برای ایجاد یک جریان پردازش کامل است.
